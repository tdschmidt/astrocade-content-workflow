# Current plan: discover, play, capture, edit

This is the source of truth for the `codex/core-workflow` branch. The user's latest clarification narrows the deliverable to finding suitable Astrocade games, learning and capturing gameplay, and producing good short videos through a simple CLI. Account creation/publication are manual; no GUI is required. The [acceptance record](docs/acceptance.md) tracks current proof; older research retains historical evidence, not additional requirements. See the appended scope decisions in [design-decisions.md](docs/design-decisions.md).

## Intended result

`npm run pipeline` produces one finished portrait highlight, posting copy and an inspectable evidence trail. It should explain why games were tried, what controls were observed and executed, what happened in the footage, and why the chosen cut makes sense. These are observations, actions, results and concise decision summaries, not private internal model reasoning.

Use ordinary TypeScript functions with Zod boundaries, Playwright native input/capture, Google model calls and FFmpeg. Each invocation owns a local run directory; a lock prevents simultaneous writes to the same run. The branch removes the GUI, application server, account/publishing and research modules. The earlier implementation remains on `main`. Four runtime libraries are sufficient: `@google/genai`, Playwright, tsx and Zod. No database, queue, agent framework, deployment or public media hosting is needed.

## Pipeline and boundaries

| Stage | Implementation | Evidence and stop condition |
| --- | --- | --- |
| Discover and nominate | Read live public Astrocade pages, retain URLs/visible metadata, nominate up to three candidates by default (configurable 1–5). Consider understandable objectives, visible consequences, portrait readability and plausible controls. | `discovery.json` and `shortlist.json` distinguish facts from hypotheses. Unlabeled counters do not become invented popularity. No live catalog is a visible failure. |
| Inspect and learn | Save the actual game surface before/after a recognized Start action and visible instructions. Reuse a tested profile where available; otherwise propose a bounded timed action plan from this evidence. | Save screenshots, control evidence and limitations. Skip uncertain controls and randomized matching/sorting puzzles that need fresh-board reasoning. A learned proposal remains unverified; model confidence is not proof of successful play. |
| Play and capture | Run supported inputs in a fresh, dedicated browser. Start native tab recording, execute the bounded plan, release inputs, flush/decode the VP9 source and close the browser. | Preserve control/capture manifests and original footage. Handle loading overlays and actual displayed game geometry. A source file proves recorded behavior, not a win or a good short. |
| Analyze and choose | Inspect every completed candidate recording. Clips up to 45 seconds use one full 8 FPS pass with absolute timestamps; longer sources retain coarse/dense inspection. Compare actual usable action to choose the winner. | Save source intervals, visible setup/action/result and uncertainty. Reject out-of-bounds timestamps. Exact numeric claims require clear, consistent evidence; no useful event means no fabricated edit. |
| Edit and render | For short sources, retain up to two seconds before the observed impact and one second after, bounded by an explicitly observed unobscured playable span. The model chooses one event index; code uses its whole context window and builds the caption directly from the selected observed outcome. Render H.264, 1080×1920, 30 fps with a fixed hook header and credit footer around the full game view. | Save `edit.json`, `highlight-*.mp4` and `caption.txt`. No model-trimmed blink, padding, repeated payoffs, arbitrary minimum duration or unsupported hook claims. Current core highlights are silent. |

The learner deliberately supports simple repeatable input. It does not attempt universal gameplay, frame-by-frame puzzle solving or guaranteed wins. If controls depend on unobserved state, skip the game and explain why. Good source footage is the bottleneck; more output formats or automation infrastructure do not resolve it.

## Operation and recovery

The CLI exposes `--stage discover|capture|edit|all`, `--game ID_OR_SLUG`, `--candidates 1-5`, `--model MODEL` and `--resume RUN_DIRECTORY`. Default model: `gemini-3.5-flash`. Discovery includes provisional nomination; capture also performs missing discovery/learning; edit requires a saved source. See [README](README.md) for exact installation and commands.

Save completed sources, analysis, edit decisions and outputs as work finishes. Resume reuses them rather than repeating paid calls or gameplay. Record each artifact's model; changing `--model` only affects unfinished work. Hash checks reject changed source/output files. A different shortlist or reconsideration of completed judgments starts a new run. Cancellation cleans up owned browser/media resources and retains completed artifacts; failures remain in `report.md` and `trace.jsonl`. Completed runs validate/reuse output without retrying failed candidates or requiring a model key. Once a script exists, resume freezes candidate capture/analysis and only finishes rendering; final caption text is reconstructible.

Model operations retry only HTTP 429/503, at most three total attempts within 120 seconds, honoring `Retry-After` rather than looping blindly. A live request succeeded on its third attempt after two 30-second server-directed waits. Provider-facing JSON schemas omit array `maxItems`; literal values use singleton enums for compatibility. The original Zod schema still checks complete output locally. Compatibility does not weaken action/timestamp limits. Candidate-specific schema/timestamp failures are recorded and skipped; provider/authentication errors stop the run without labeling a game unsuitable.

Each run retains `run.json`, `report.md`, `trace.jsonl`, live discovery/shortlist JSON, before/after inspection images, control profiles, capture manifests/source files, analyses, the edit plan, final MP4 and caption. Keep credentials and browser sessions out of shared evidence. The trace records what the workflow did and concluded, including failures; it is not a transcript of internal reasoning.

## Verified result and limits

Live discovery has returned 30 games. Crowd Pier Run has passed repeated native capture, and real footage has passed decoded portrait rendering with the complete HUD visible. Offline regression tests cover model boundaries and the context-preserving cut/fixed-layout behavior. An earlier focused CLI run produced an inaccurate “multiplier” caption, which led to direct-outcome captions. The later three-candidate run produced the accepted functional result below.

The automatically shortlisted run captured Crowd Pier Run (12.915s), Manu Tap-Tap Shots (3.611s), and Bladefish.io (10.316s). The final Crowd Pier Run highlight passed visual/media review: 3.766667s, 1080×1920, H.264/yuv420p, 30 fps, silent. Its complete HUD, +5 gate approach, visible crowd change 8→13, and matching hook/caption form a truthful short. Newly learned controls produced the latter two recordings, but analysis rejected their footage for lacking a supported payoff. Flash hit the test project's reported 20-requests/day free quota after earlier overload responses, so an explicit edit-stage resume used Flash Lite and preserved the completed Flash analysis. This is functional and conservative editorial acceptance, not a claim of viral quality or broad game mastery. Bounded controls can yield movement without a payoff; the pipeline rejects such footage. Preserve the shortlist, controls, source footage, model provenance and rejected candidates so the reviewer can inspect that distinction. Numeric/model accuracy still needs review on future runs.

Completion for this branch means a reproducible live run produces a watchable, truthful short with an understandable decision/consequence, plus the complete code and evidence explaining it. Account creation and uploading are manual follow-through; future publishing should consume the reviewed video/caption. The removed GUI/account/research paths do not expand this branch's acceptance criteria. A clean install, typecheck, doctor and all 79 retained opt-in tests passed with no skips. A real completed-run resume reused the video in under one second with no candidate/model work. No GUI build is part of the handoff.
