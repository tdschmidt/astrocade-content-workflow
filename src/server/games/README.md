# Game discovery and capture support

`discoverGames` reads public Astrocade links from live pages. An inaccessible source is reported as `unreachable`/`unavailable`; cached research is never returned as live discovery. `parsePublicMetrics` retains only labeled public counters. The CLI's nomination stage in `src/core/selection.ts` assesses the candidates against the content brief; a title or popularity counter alone cannot prove useful gameplay.

`Crowd Pier Run` is the first verified preset. Repeated native captures produced about 13 seconds of moving gameplay with changing crowd counts. See [acceptance evidence](../../../docs/acceptance.md) for the historical recordings. The active workflow is local discovery, capture, analysis and editing; it has no Studio, account setup or publishing stage.

For unfamiliar games, `inspectGamePage` observes the live viewport, menu and instructions before `learnGameProfile` or `learnFeedbackProfile` creates a bounded control profile. Capture rejects unverified profiles unless the calling workflow explicitly enables an exploratory attempt. Technical verification requires two independent decoded recordings; meaningful content is assessed during generation. A new supported preset also needs live inspection of its controls and actual footage.

Profiles contain selectors, bounded input steps, and controller settings, not arbitrary scripts. The `timed` controller uses a finite action sequence; the `sparse` controller compares previous/current screenshots, visible DOM text and prior inputs through an injected decision provider. The CLI exposes it as `--play feedback` for slow/input-paced games. It tests one reversible input first, then uses bounded batches, one-second effect settling and recent observed lessons. Each session saves a screenshot report; completion remains subject to independent footage analysis. Inputs are native Playwright events with bounded holds and cleanup. Pointer coordinates are normalized relative to the current surface bounds, including iframe positioning. Unfamiliar reflex games may require a new controller and should be skipped instead of pretending a configuration change solves them.

`runCaptureAttempt` owns one recorder session, begins recording before start actions, stops at its duration budget, and always releases inputs/closes the session. It returns a finalized artifact plus attempt evidence; editorial analysis still determines whether it contains a meaningful event. A reset is a verified UI sequence or a reload; fresh recorder/browser contexts are used for separate attempts.

The pure tests run with the normal test command. Browser fixture tests additionally require `RUN_BROWSER_TESTS=1` and installed matching Playwright Chromium. Their local synthetic game is explicitly a fixture and never reported as Astrocade footage.

Car Wash now ships a model-revised timed profile tested to a Perfect first-customer result in independent fresh recordings. Its shift timer makes live multi-second inference inappropriate. Sort It Out demonstrates current-board feedback; it uses learned rules and fresh screenshots rather than stored puzzle coordinates. Both examples have failed and successful attempts in the acceptance record.
